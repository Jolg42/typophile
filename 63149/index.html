Using words do make it easier for people to solve the CAPTCHA, but it also makes it much easier for a computer program to solve. Using words is a terrible idea if a site is trying to stop frequent attacks from computer programs, but probably just fine if the site isn’t expecting someone to write custom programs to break your CAPTCHA. I worked on a project where we investigated how to build a CAPTCHA that would be recognizable by people, but not by computer programs. [http://research.microsoft.com/en-us/um/people/kumarc/pubs/chellapilla\_ch...](http://web.archive.org/web/20130820033339/http:/research.microsoft.com/en-us/um/people/kumarc/pubs/chellapilla_chi05.pdf "http://research.microsoft.com/en-us/um/people/kumarc/pubs/chellapilla\_chi05.pdf") Interestingly, computer programs recognize single characters at a higher rate than people. To build an effective CAPTCHA you need to make it difficult for the computer program to segment the location of each of the characters. Allowing words instead of pseudowords adds the benefit of the possibility of using scanned texts, so that the decoding can not only verify a human reader, but also as a side effect advance the deciphering of scans. See [this page about reCAPTCHA](http://web.archive.org/web/20130820033339/http:/recaptcha.net/learnmore.html).
