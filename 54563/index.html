Anonymous @ 8 Feb 2009 — 3:10pm
**James:** _I get those weird shapes all the time, but undo usually fixes things._ This probably has to do with the way FL manages undo (it is: one thread by glyph, so as, after some glyph jumps, one increases geometrically undo memory usage) through multiple dynamic pointers; eventually, it may occur that, when you try to go back i.e. by typing a fast keystroke, you “catch” FL —which is modestly slow due to its complexity— performing another background task; that's why you can fix it —actually, not exactly a bug, but an undesired undoable behavior— by repeating the command: after recovering its “conscious”, FL finishes all pending tasks and brings you where you wanted to. **MarS**

Anonymous @ 8 Feb 2009 — 5:23pm
As soon as a path starts behaving oddly, I do this: First, if necessary, undo to the point where the outline looks okay. Then select the entire path, cut and then paste. This seems to always clear up erratic path behavior for me. I also have a habit of saving frequently. I don't trust auto-save because it may save the font in an undesirable condition, like right after I've done something I shouldn't have to the font. I also use the option to save .bak files, so I can always roll back one version. Failing that, TimeMachine on OS X is my fallback (and it has saved me at least once).

You can't run it for too long, run long with several other applications running, with a large glyph repertoire refreshing, or edit a high resolution font at large magnification, without crashes likely to occur.
