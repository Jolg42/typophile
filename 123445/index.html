Here is a more useful script that lists not only the tags but their associated scripts and languages and that can be used to check for consistency. #!/usr/bin/env python import fontforge,sys filename=sys.argv[1].decode('utf-8') lstfonts = fontforge.fontsInFile(filename) def languages(ll): return '; '.join("%s{%s}" % (s[0], \ ', '.join(l for l in s[1])) \ for s in ll) def disptable(fnt): for t in ['gsub', 'gpos']: print " %s:" % (t) lkp = eval("fnt.%s_lookups" % (t)) for p in lkp: v = fnt.getLookupInfo(p)[2] if v: print " %s: %s" % \ ((v[0][0]), languages(v[0][1])) for f in lstfonts: print "-----\n%s\n-----" %(f) fnt=fontforge.open("%s(%s)" % (filename,f)) disptable(fnt) Let us now come back to what can be done and what may be done. Anonymous @ 3 Mar 2015 — 12:40pm
I wrote a script that takes as input a font (ttf, otf, ttc and even dfont) and that lists features. I provided no script to modify a font in any way. In order to "fix" the fonts, you need no script at all. To copy the GSUB tables, when the EULA allows it, you open the two fonts with FontForge, the one with the missing GSUB tables and the one from which to copy. In the font with the missing GSUB tables you select "Element \> Font Info \> Lookups" and then "GSUB" and you click "Import". You will then see the lookups from the other font. You select them and then click OK. That is it. That assumes that the glyph names are the same in the two fonts, which I guess is good practice for a font designer if one font is the regular and the other is the bold or the black. With a ttc font, you probably need to split before; Apple's `ftxsplitter` does that.
