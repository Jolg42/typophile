Type designers, do your font licenses allow iTunes LP embedding?

Who saw this coming? ;-)

http://jayrobinson.org/2009/09/11/some-notes-on-itunes-lp/

Scroll down to “WebKit and iTunes LP Internal Structure”

The iTunes LP experience is accomplished with HTML 4.01, CSS and JS. The interface feels very Flash-like, but there is no trace of it. The CSS animations are elaborate and smooth. Font files are referenced with an @font-face declaration in the CSS but there seems to be little to no use. Most text, even long passages of lyrics, is represented visually with a PNG file. I wonder if they originally intended to use font replacement for all text, but changed their mind.

Font licensing fun aside I wonder what the image-centric nature of the text does for accessibility?

From Apple's "Design Best Practices" document: &nbsp; &nbsp; &nbsp; **Fonts and Scrollbars** &nbsp; &nbsp; &nbsp; • &nbsp; **_Don’t use Open Type._** When using fonts, use SVG fonts, which &nbsp; &nbsp; &nbsp; are small, render quickly, and scale better. The fonts to be turned &nbsp; &nbsp; &nbsp; into SVG fonts need to be legally cleared for use within the iTunes &nbsp; &nbsp; &nbsp; LP or iTunes Extras, and should be distributed in the package as an &nbsp; &nbsp; &nbsp; SVG font to restrict consumer usage of the font. &nbsp; &nbsp; &nbsp; However, it is often better to use images rather than SVG fonts. &nbsp; &nbsp; &nbsp; See the next two suggestions. &nbsp; &nbsp; &nbsp; • &nbsp; **_Use buttons instead of live text for menus._** Use images for menu &nbsp; &nbsp; &nbsp; buttons, instead of an SVG font. This has a couple of advantages: &nbsp; &nbsp; &nbsp; » Rendering is the same on all platforms (Mac, Windows, Apple TV). &nbsp; &nbsp; &nbsp; » You have more control over spacing of text since you can use kerning &nbsp; &nbsp; &nbsp; and other ways to make the text smaller or bigger, depending on how &nbsp; &nbsp; &nbsp; much space the design allows. &nbsp; &nbsp; &nbsp; » No potential fonts rights issue. &nbsp; &nbsp; &nbsp; • &nbsp; **_Use a JPEG for large blocks of text._** Instead of using live text from a &nbsp; &nbsp; &nbsp; font for a song list or lyrics, make the list or lyrics an image. &nbsp; &nbsp; &nbsp; You have more control over sizing and spacing, which can be useful on &nbsp; &nbsp; &nbsp; lyrics pages where space is limited or for long, one-line lyrics that &nbsp; &nbsp; &nbsp; might not fit. &nbsp; &nbsp; &nbsp; JPEGs are smaller than fonts and compressed, so one small image gets &nbsp; &nbsp; &nbsp; loaded into memory instead of larger-sized font elements. &nbsp; &nbsp; &nbsp; By putting lyrics in an image, the text can’t be copied and pasted (legal &nbsp; &nbsp; &nbsp; considerations). &nbsp; &nbsp; &nbsp; Rendering is the same on all platforms. &nbsp; &nbsp; &nbsp; No fonts rights issue (if there ever would be one).
