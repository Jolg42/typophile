Merging and converting PS1 fonts to OpenType

I was recently setting some text in FF Scala Sans (PS1 fonts) in InDesign and was annoyed by the need to constantly switch between, say, Scala Regular and Scala Regular SC in order to get real small caps. So I decided to use FontLab 5 to convert the PS1 fonts into OpenType, starting with the Regular font and adding to it the small caps, lining figures etc from the complementary fonts.

The idea sounds simple enough, but in order to make the resulting OpenType font do what I wanted in InDesign, I decided to use a native Adobe OS font (Minion) as a template and started copying the glyphs to the same places. So for starters I had to move the proportional text figures from their original place in the Scala Sans Regular font to U+F730 — U+F739 in the new OpenType font, then copy the lining figures to U+0030 — U+0039, then the small caps also to the private use area (but to two different blocks, one for the accented and another for the unaccented glyphs), and so on.

Then of course I had to create all the substitution classes in FontLab for ligatures, proportional text figures etc etc etc.

By the time I was done with the new Scala Sans OS, I had all but given up on the idea of doing the same thing all over again for the italic, then the bold, then all the condensed fonts.

Does anyone know of a simpler way to accomplish this conversion? Isn’t there a nice little tool out there somewhere that lets you choose the source fonts and automatically creates a new OpenType font, transfering the relevant glyphs from the different source fonts to the right places in the new OS font?

Anonymous @ 20 July, 2006 - 9:40am
Erik, I use following procedure to merge single fonts into an OT. This is reliable for large families, not for single fonts. 1) I analyze the glyphs from the additional fonts. I create a list of glyphs I should add to the basic font from each separate font (OSF, CE, Expert…) 2) I rename the glyphs to be added to the basic font (one –\> one.oldstyle, A –\> A.small, at –\> at.alt…). I’ve found free Python scripts for easier renaming of the glyphs 3) I create encoding scheme which only includes the glyphs I need to copy to the basic font 4) I append new glyphs to the basic font 5) I save the renaming schemes and encodings to comfortably build all the fonts in a family 6) I solve problems and irregularities in the fonts (not all Expert fonts in one family share the same number of glyphs, some fonts have missing or wrong characters etc.) 7) I do the technical stuff (family renaming, setting of proper encodings, building OT naming, adding invisible glyphs etc.) 8) I generate OT features (I have a collection of scripts doing this automatically according to glyph suffices) 9) If necessary, I expand kerning to accented glyphs (some fonts contain kerning for pairs with one accented glyph only, they don’t have fonts with two accented glyphs; I have a script doing this in a very smart way) 10) I export the fonts. Some of the steps could be made easier in FL Studio 5 using Merge Fonts feature.
